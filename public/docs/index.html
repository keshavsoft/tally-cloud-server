Unified Tally Architecture: The Complete Story

How we re-architected the entire four-repository ecosystem (tally-xml-tdl, tally-to-json, tally-local-server, and tally-cloud-server) around Tally's native <TYPE> hierarchy, enabling deep master dimensions like withBatches, robust WebSocket tunneling, and modular frontend views.

1. The Need: From Flat Names to Canonical <TYPE>

Historically, Tally commands were exposed through disparate, ad-hoc naming patterns like stockItems, uom, ledgers, and groups. This created impedance mismatch with Tally's native TDL, where every master object adheres to a strictly defined XML attribute: <TYPE>Unit</TYPE>, <TYPE>StockItem</TYPE>, <TYPE>Ledger</TYPE>, etc.

Furthermore, real-world business needs demand granular variations: querying basic names only, querying base units, or querying multi-godown batch allocations with opening balances and valuations.

Master Entity Old Flat Command New Canonical <TYPE> Hierarchy Sub-Variant Capabilities
Stock Item stockItems StockItem all, names, withBaseUnits, withBatches
Unit of Measure uom Unit all, names
Accounting Ledger ledgers Ledger all, names
Stock Group stockGroups StockGroup all, names

3. Cloud Server Core Enhancements

In tally-cloud-server/routes/v2/dispatchCommand.js, two foundational architectural guidelines are enforced:

Guideline B: Context Forwarding

All query parameters (e.g. ?company=mani9) and request bodies are packaged into the WebSocket message: { command, query: req.query, body: req.body }. The local server receives complete context for every execution.

Guideline C: 30-Second Safety Timeout

Every pending HTTP-to-WS request tracks a timeoutId. If the local server or Tally fails to respond within 30 seconds, it cancels cleanly and returns an HTTP 504 Gateway Timeout instead of leaving browser connections hanging.

5. Parameter Naming Convention: in and local

All JavaScript functions strictly adhere to the project's explicit input traceability pattern:

Standard Javascript Function Pattern Convention Rule 
// 1. Functions accept a single configuration object with 'in'-prefixed keys
export function fetchStockItemsWithBatches({ inCompany, inFilterOptions }) {
    // 2. Immediately map 'in' parameters to 'local' variables at the top
    const localCompany = inCompany;
    const localFilterOptions = inFilterOptions;

    // 3. Exclusively use 'local' variables throughout the function body
    const url = `/ws/StockItem.withBatches?company=${encodeURIComponent(localCompany)}`;
    return fetch(url);
}
